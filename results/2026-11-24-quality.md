# Quality vs. the 8-bit reference (2026-11-24)

> Update: the same comparison against the native weights is in
> [`2026-11-24-quality-native.md`](2026-11-24-quality-native.md).

**Question:** how much do the two 4-bit builds we benchmark lose? We cannot run the native checkpoint
(BF16 dense + NVFP4/MXFP8 experts, NVIDIA ModelOpt format) on an Intel GPU today, so the reference is Unsloth's
**UD-Q8_K_XL** GGUF, which Unsloth describes as effectively lossless.

**Method:** wikitext-2 test set, 150 chunks × 512 tokens, second half of each chunk scored (38,250 positions),
exactly as `llama-perplexity` does.

1. `llama-perplexity --kl-divergence-base` on UD-Q8_K_XL (llama.cpp Vulkan, Unsloth build b12631).
2. `llama-perplexity --kl-divergence` on UD-Q4_K_XL against that base.
3. The EXL3 4bpw build served by vLLM: the **same token ids** sent with `prompt_logprobs`, scored at the same
   positions and compared with the base file ([`bench/quality_vs_kld_base.py`](../bench/quality_vs_kld_base.py)).
   Sanity check: the reference perplexity recomputed from the base file by this script is 6.9371, and
   `llama-perplexity` reports 6.9373. Same tokens, same positions.

## Results

| Build | Engine | PPL | PPL vs Q8 | Top-1 agreement with Q8 | Mean KLD vs Q8 |
|---|---|---|---|---|---|
| UD-Q8_K_XL (reference) | llama.cpp Vulkan | 6.937 ± 0.087 | — | — | — |
| UD-Q4_K_XL | llama.cpp Vulkan | 6.940 ± 0.087 | **+0.04 %** | **98.0 %** | **0.0024** (median 0.0009, p99 0.023) |
| EXL3 4bpw | vLLM XPU (B70 recipe, FP8 KV) | 6.960 | **+0.33 %** | **96.4 %** | not computed* |

\* The server returns only the top token per position, not the full distribution, so KLD cannot be computed for
the vLLM build. Top-1 agreement and perplexity are measured on identical tokens.

## Reading the numbers

- **Both 4-bit builds are close to the 8-bit reference.** The GGUF Q4 is essentially indistinguishable
  (+0.04 % PPL, 98 % same top token, matching Unsloth's published 98.0 %).
- **The fast vLLM build costs a bit more** (+0.33 % PPL, 96.4 % same top token). The comparison crosses engines,
  so this also includes vLLM's numerics and its **FP8 KV cache**, not only the EXL3 weights.
- **Limits:** the reference is Q8, not the native checkpoint. Perplexity on wikitext is a proxy, not a task
  benchmark (the recipe author reports coding-task results for the EXL3 build). Single run, one card.
